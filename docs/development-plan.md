# 📋 학습 확인 퀴즈 생성 서비스 개발 계획서 (Master Development Plan)

> **기준 문서**: [`PRD.md`](file:///c:/study_zip/PRD.md)  
> **프로젝트 목표**: 사용자가 입력한 학습 텍스트를 바탕으로 기본개념 2문제 + 응용 3문제(총 5문제)를 생성하고, 즉시 풀이 및 채점/해설을 제공하는 단일 화면 웹 서비스 구현

---

## 1. 프로젝트 개요 및 제약 사항

### 1.1 핵심 가치 및 목표
- **단일 화면 (Single Page State Transition)**: 라우팅이나 별도 페이지 이동 없이 단일 화면 내 상태 변화(Input → Loading → Quiz → Result)만으로 완결되는 UX.
- **5문제 생성 구조**: 기본개념 2문제 + 응용 3문제 고정.
- **빠른 응답 속도**: 텍스트 입력 후 퀴즈 생성까지 평균 15초 이내 완료.
- **단순하고 명확한 범위 (Out of Scope)**: 로그인, 결제, DB, 파일 업로드/저장 일체 배제 (새로고침 시 상태 초기화는 의도된 설계).

### 1.2 기술 스택
- **Framework**: Next.js 16 (App Router), React 19, TypeScript
- **Styling**: Tailwind CSS v4, Lucide React
- **AI/LLM Engine**: Google Gemini API / OpenAI API (구조화된 JSON Schema 출력 활용) + 오프라인/테스트용 지능형 Fallback Generator

---

## 2. 스프린트 마일스톤 (Sprint Milestones)

전체 개발은 **4개의 스프린트**로 분할하여 점진적이고 안정적으로 개발을 진행합니다.

```mermaid
graph LR
    S1[Sprint 1<br/>기반 구축 & 입력/예외] --> S2[Sprint 2<br/>AI 퀴즈 생성 엔진]
    S2 --> S3[Sprint 3<br/>풀이·채점·결과 고도화]
    S3 --> S4[Sprint 4<br/>종합 예외 & DoD 검증]
```

| 스프린트 | 주요 목표 | 핵심 산출물 | 예상 완료 기준 |
| :--- | :--- | :--- | :--- |
| **Sprint 1** | 입력 검증 및 상태 관리 기반 구축 | 입력 유효성(5-1, 5-2, 5-3), 입력 UI 고도화 | 글자 수(100~3,000자) 검증 완료 |
| **Sprint 2** | AI 퀴즈 생성 백엔드 API & 로딩/타임아웃 | LLM 연동 API Route, 로딩 UI, 타임아웃(30초) | 5문제(개념2+응용3) JSON 정상 수신 |
| **Sprint 3** | 퀴즈 풀이 및 채점/해설 엔진 고도화 | 객관식/주관식/혼합 풀이, 유연한 주관식 채점 | 미응답 처리(5-6), 점수/해설 시각화 |
| **Sprint 4** | 전방위 예외 처리, 재생성 및 DoD 최종 검증 | 실패 복구(5-4, 5-5), 반응형 UI, DoD 100% 달성 | 7대 예외 케이스 및 데모 검증 완료 |

## 3. 세부 스프린트 계획

### 🚀 Sprint 1: 입력 영역 및 사전 예외 처리 고도화
- **목표**: PRD Section 3 (영역 A) 및 Section 5 (5-1, 5-2, 5-3) 완전 구현
- **상세 태스크**:
  1. **입력 텍스트 길이 정책 구현**:
     - `5-1` 빈 텍스트 입력 시: `"학습 내용을 입력해 주세요"` 경고 및 텍스트창 포커스.
     - `5-2` 100자 미만 입력 시: `"학습 내용을 조금 더 길게 써주세요 (최소 100자)"` 안내.
     - `5-3` 3,000자 초과 입력 시: `"입력이 너무 깁니다. 3,000자 이내로 줄여주세요"` 에러 표시 및 글자수 카운터 UI 제공.
  2. **문제 유형 선택기(Segmented Control/Radio) 연동**:
     - `객관식(4지선다)`, `주관식(직접입력)`, `혼합(객관식+주관식)` 선택 상태 동기화.
  3. **실시간 유효성 피드백 & 상태 리셋 로직**:
     - 입력 수정 시 에러 즉시 해제.

---

### 🚀 Sprint 2: 퀴즈 생성 백엔드 API 및 로딩/타임아웃 핸들러
- **목표**: PRD Section 4-1 (문제 생성) 및 Section 5 (5-4, 5-5 a/b) 구현
- **상세 태스크**:
  1. **Next.js API Route 구축 (`/api/quiz/generate`)**:
     - LLM Prompt 엔지니어링: 학습 텍스트 기반 기본개념 2문항 + 응용 3문항 강제.
     - 유형별(객관식/주관식/혼합) 포맷에 맞는 정형 JSON 스키마 응답.
     - API Key 미설정 또는 네트워크 장애 시 동작하는 Fallback Mock 엔진 연동.
  2. **영역 B 로딩 & 타임아웃 UX (`5-4`)**:
     - "퀴즈 생성" 버튼 중복 클릭 방지 (비활성화 처리).
     - 30초 초과 시 타임아웃 감지 → `"응답이 지연되고 있습니다. 다시 시도해 주세요"` + 재시도 버튼 노출.
  3. **생성 오류 자동 감지 (`5-5 a, b`)**:
     - 5문항 미만 또는 스키마 불일치 감지 시 오류 안내 및 재시도 UX 제공 (기존 입력 텍스트 보존).

---

### 🚀 Sprint 3: 풀이, 채점 및 결과/해설 인터페이스 완성
- **목표**: PRD Section 3 (영역 C, D) 및 Section 4-2, 4-3, 5-6 구현
- **상세 태스크**:
  1. **영역 C: 문제/응답 인터페이스**:
     - 문제 1~2번 `[기본개념]` 배지, 3~5번 `[응용]` 배지 표시.
     - 객관식 4지선다 라디오 UI + 주관식 인풋 UI.
     - 풀이 진행률(예: 3 / 5 응답) 실시간 카운팅.
  2. **채점 엔진 (`4-3`)**:
     - 객관식: 선택지 인덱스 정밀 비교 (100% 일치).
     - 주관식: 공백/대소문자 정규화 및 핵심 키워드 매칭 로직.
     - `5-6` 미응답 허용: 미응답 문항은 오답 처리 및 결과 화면에 `[미응답]` 배지 표기.
  3. **영역 D: 결과 요약 및 해설**:
     - 정답 수 및 정답률(%) 시각화.
     - 문제별 사용자 답안 vs 정답 + 상세 해설 노출.
     - "다시 만들기" 버튼 클릭 시 입력창으로 상태 복귀.
